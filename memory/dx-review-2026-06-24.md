# Design: MarketPOS Developer Experience Overhaul

Generated by plan-devex-review on 2026-06-24
Status: DRAFT
Mode: Solo developer + AI tools

## Problem Statement

Building on MarketPOS works but with friction. The working tree is a swamp (136 untracked files vs 190 tracked), scratch files and debug scripts are mixed with real source, AI tools start every session from zero context, the API test runner is a custom non-standard build-before-test loop, desktop dev is Windows-only, and there is no linter (typecheck is the only quality gate). A solo developer using AI tools loses time to archaeology and confused agents on every session.

## DX Scores (Current State)

|---|---|---|---|
| 1 | Usable | 4/10 | No onboarding guide, no .env.example, no DB setup steps |
| 2 | Credible | 5/10 | Two vitest versions, turbo configured but README says manual builds |
| 3 | Findable | 3/10 | No dev docs, debug scripts mixed with source, no AGENTS.md |

| 7 | Desirable | 5/10 | Modern stack but tooling is rough |

Composite: 4.3/10 ("Acceptable. Works but with friction. Developers tolerate it.")

## What Makes This Better

The magic moment: sit down, open the repo, AI tools immediately understand the project. Clean git status. One command runs all tests. One command lints everything. No scratch files, no debug scripts, no mystery files. Every session starts with context instead of archaeology.

## Premises

1. The #1 DX problem is one root cause with two symptoms: messy working tree + no agent guidance file. Both share one fix: clean the tree + add AGENTS.md.
2. For a solo dev + AI tools, AGENTS.md matters more than CONTRIBUTING.md.
3. Custom API test runner, Windows-only scripts, and missing linter are real but secondary. Fix incrementally after the working tree and AI context are clean.

## Approach Chosen: C - Full DX Overhaul

Rationale: User chose full overhaul. While the #1 pain is the working tree, addressing dev loop friction and linting in the same pass prevents a second round of disruption. The scope is ambitious but the user is solo and can control the pace.

### Phase 2: AI Tool Context (S, zero risk)

Contents:

### Phase 3: Dev Loop Fix (M, medium risk)

**3.1 Replace custom API test runner with vitest**
- Install vitest in api-server
- Create `vitest.config.ts` for api-server (ESM, TypeScript path aliases)
- Migrate `tests/run-tests.mjs` test cases to vitest test files
- Remove `tests/register-loader.mjs` and custom build-before-test step
- Update package.json: `"test": "vitest run"` (matching pos-desktop and web-dashboard)
- Verify all existing API tests pass under vitest

**3.2 Sync vitest versions**
- Decide on one version: vitest ^4.1.2 (pos-desktop's version, latest)
- Update web-dashboard devDependencies from ^2.1.8 to ^4.1.2
- Run web-dashboard tests to verify compatibility
- Update vitest config if API surface changed between 2.x and 4.x

**3.3 Make electron:dev cross-platform**
- Replace PowerShell `free-port:5175` with a cross-platform Node script (`scripts/free-port.mjs`)
- Replace inline `set "ELECTRON_RUN_AS_NODE="` with `cross-env`
- Install `cross-env` as devDependency
- New electron:dev: `concurrently -k -s first "npm run dev -- --strictPort --port 5175" "npm run watch:electron" "wait-on http://localhost:5175 file:dist-electron/main.js file:dist-electron/preload.js && cross-env ELECTRON_RUN_AS_NODE= electron ."`
- Verify on Windows (current dev environment)
- Document Linux/macOS requirements (if any native deps differ)

### Phase 4: Linting + Formatting (M, low risk)

**4.1 Add Biome**
- Install `@biomejs/biome` at repo root
- Create `biome.json` with sensible defaults (formatting + lint rules)
- Configure to cover all packages (TypeScript, TypeScript React, JSON)
- Add scripts to root package.json: `"lint": "biome lint ."` and `"format": "biome format --write ."`
- Keep `"typecheck"` as separate turbo task (typecheck and lint are different concerns)
- Update turbo.json: `"lint"` task no longer depends on `^lint` (Biome runs on the whole repo), or configure per-package Biome

**4.2 Replace per-package lint aliases**
- Remove `"lint": "npm run typecheck"` from all package.json files
- Each package's `"lint"` script becomes inherited from root Biome, or explicitly runs `biome lint <package-dir>`
- Keep `"typecheck"` scripts as-is (they remain valuable as a separate check)

### Phase 5: CI Unification (M, medium risk)

**5.1 Add unified quality gate workflow**
- Create `.github/workflows/quality-gate.yml` that runs all checks:
  - Repo hygiene (generated artifact guard, Prisma validate, migration guard)
  - Shared: build
  - API: build, test (vitest), typecheck
  - Desktop: lint, test, build, build:electron
  - Web dashboard: test, build, typecheck
  - Root: Biome lint
- This becomes the single "all green" gate
- Keep existing path-scoped workflows for faster PR feedback (they run subset checks)
- The unified gate runs on PRs to main and on push to main

**5.2 Add turbo run test**
- Add `"test"` task to turbo.json:
  ```json
  "test": {
    "dependsOn": ["^build"],
    "cache": false
  }
  ```
- Add `"test": "turbo run test"` to root package.json scripts
- One command runs all tests across all packages with correct dependency ordering

### Phase 6: Documentation (S, low risk)

**6.1 Add CONTRIBUTING.md**
- Development setup (clone, nvm use, npm install, env setup, DB migration)
- Build commands (turbo run build, per-package)
- Test commands (turbo run test, per-package)
- Lint/format commands (biome lint, biome format)
- Commit conventions (logical units, no scratch files, no debug scripts)
- Project structure overview
- Package boundaries (what goes where)

**6.2 Update README.md**
- Add link to CONTRIBUTING.md for development
- Add "Quick Start for Developers" section
- Keep existing pilot/operations docs section

## Open Questions

1. **API test migration risk**: The custom test runner (`tests/run-tests.mjs` + `register-loader.mjs`) exists for a reason (ESM + TypeScript import resolution). Vitest handles this natively, but the existing test structure may need refactoring. Need to audit test files before migration.
2. **Biome vs ESLint+Prettier**: Biome is faster and simpler (one tool, zero config). ESLint+Prettier is more established with more plugins. For a solo dev, Biome is the right choice. Confirm.
3. **vitest 4.x compatibility**: web-dashboard is on vitest 2.x. Jumping to 4.x may have breaking changes. Need to check vitest changelog for API surface changes.
4. **cross-env vs dotenv**: `cross-env` is the standard for cross-platform env vars in npm scripts. Confirm this is preferred over a `.env`-based approach for electron:dev.
5. **Desktop CI on Linux**: If electron:dev becomes cross-platform, should desktop CI also run on ubuntu-latest? Or keep windows-latest since the product is Windows-only?

## Success Criteria

- `git status` on a clean checkout shows no untracked files (everything is either committed or gitignored)
- `AGENTS.md` exists and AI tools reference it without prompting
- `.env.example` exists and a fresh clone can be set up by copying it to `.env` and filling in values
- `npm run test` (turbo run test) runs all tests across all packages in one command
- `npm run lint` (Biome) runs across the entire repo in under 10 seconds
- API tests run via `vitest run` (no build step required before tests)
- `electron:dev` works on Windows AND Linux/macOS
- CI has a unified quality gate that blocks PRs if any check fails
- `CONTRIBUTING.md` exists and a new developer can set up the project by following it
- Composite DX score improves from 4.3/10 to 7.0+/10

## Dependencies

- No external blockers
- vitest 4.x compatibility check for web-dashboard tests
- Biome config needs to be tested against existing codebase (may surface many lint issues on first run)
- API test migration requires understanding the custom runner's test structure

## The Assignment

Before starting Phase 1: run `git status` and categorize every untracked file into "real source to commit" vs "temporary artifact to delete/gitignore." Create a checklist. This takes 30 minutes and turns the swamp into a plan.
